## 2. Architecture

Pattern summary (to name at the discussion):
- **Factory / Registry**: encoders are built from a name in the YAML config.
- **Strategy**: interchangeable encoders, trackers, and search samplers (Grid / Random).
- **Template Method**: `Trainer` fixes the step order (batch, forward, loss, backward, log, validate).

Every encoder implements one contract:
- `forward(x)` returns a batch of feature vectors.
- `feature_dim` is the vector size.
- `gradcam_layer()` returns the layer Grad-CAM hooks into.

`Classifier = Encoder + Head` where `Head = Dropout -> Linear(feature_dim, 200)`, shared by all encoders. The `Trainer` takes `(model, dataloaders, optimizer, tracker)` and never imports a concrete encoder. Milestone 2 attaches a decoder to the same `Encoder` object.

## 3. Data and EDA

- Source: `Multimodal-Fatima/CUB_train` (5,994 images) and `CUB_test` (5,794 images).
- Validation: stratified 80/20 split of train with a fixed seed, about 4,795 train and 1,199 validation. Rationale: about 6 validation images per class keeps per-class metrics and tuning comparisons usable (about 1.15% standard error on an 80% score). The test set is used only for final numbers.
- EDA (`python -m src.cli eda`, output in `outputs/eda/`):
  - Images: class balance, size and aspect-ratio spread, non-RGB or grayscale files (converted to 3 channels), corrupt files, near-duplicates by hashing.
  - Captions: split `description` on `\n`, verify 10 per image, then length, vocabulary, rare words, probable typos, empty or duplicate lines.
  - Cleaning: lowercase, strip whitespace, drop empty lines, fix typos and noise only if the data shows they matter. Every step logged in `outputs/NOTES.md`. Output: a cleaned-captions file consumed in Milestone 2.
- Augmentation (train): resize about 256, random resized crop 224, horizontal flip, small rotation, mild colour jitter (colour is a species cue). No vertical flip. Val and test: resize and center crop. Normalisation: ImageNet mean and std for all models, so the comparison is fair. Figure: before/after augmentation examples.

## 4. Models

- **ScratchCNN**: 4 to 5 blocks of Conv, BatchNorm, ReLU, MaxPool with widths 32, 64, 128, 256, 512; global average pooling; `feature_dim = 512`; about 1 to 2M parameters. Official from-scratch baseline.
- **ResNet-18, ResNet-50, EfficientNet-B0** from torchvision with ImageNet weights, original classifier removed.
- Each pretrained backbone runs in two modes: frozen (`freeze_encoder: true`, BatchNorm kept in eval mode) and fine-tuned.
- Extra ablation: ResNet-18 with random weights (`pretrained: false`), to isolate the value of pretraining with identical architecture.

Run list (8 runs): ScratchCNN; ResNet-18 random; then ResNet-18, ResNet-50, EfficientNet-B0 each frozen and fine-tuned.

## 5. Training

- AdamW, cosine learning-rate decay with short warmup; fine-tuning uses a lower backbone learning rate than head learning rate.
- Cross-entropy with label smoothing 0.1, fixed in all runs.
- Mixed precision (AMP), early stopping on validation accuracy, best checkpoint kept by validation accuracy.
- One `set_seed()` covering Python, NumPy, PyTorch and DataLoader workers.
- W&B logs per epoch: train/val loss and accuracy, learning rate, config. Best checkpoint saved under `outputs/checkpoints/` (git-ignored) and referenced as a W&B artifact. Final models also go to the Drive link required by the deliverables.

## 6. Hyperparameter tuning

- Model: ResNet-18, pretrained, fine-tuned. Score: validation accuracy.
- Hyperparameters: learning rate, weight decay, head dropout.
- Grid: lr in {1e-4, 3e-4, 1e-3} x wd in {1e-4, 1e-2} x dropout in {0.2, 0.5} = 12 trials.
- Random: 12 trials, lr and wd log-uniform over the same ranges, dropout uniform in [0.2, 0.5]. Equal budget for a fair comparison.
- Each trial trains about 8 epochs with the same seed. Estimated about 3 minutes per trial on a T4 (to be measured). The best setting is retrained once at the full epoch budget.
- Code: `Sampler` interface with `GridSampler` and `RandomSampler`; `Tuner` loops trials and calls `Trainer`; one W&B group per method.
- Report outputs: table (best score, trials, total time, best parameters per method), best-so-far vs trial plot, score vs learning-rate scatter. Differences under about 1 point are within noise and are reported as such.
- Optuna is not used.

## 7. Grad-CAM and evaluation

- Grad-CAM on the last conv block of each encoder via `gradcam_layer()`. Examples: confident-correct, barely-correct, confidently-wrong, and the most-confused species pair. Each shows image, overlay, true class, predicted class. Analysis is qualitative (does the model look at the bird or the background).
- Metrics: accuracy, top-5 accuracy, macro precision, macro recall, macro F1, confusion matrix (report shows most-confused pairs and per-class F1 because 200x200 is unreadable). The report explains what each measures and what the scores mean.
- Final models are evaluated on the test set only.
- Comparison figure across all 8 runs and the tuning results.
- Benchmarking: published CUB-200-2011 classification results on the same official split with accuracy. Sources to be looked up and verified when we reach this step, not quoted from memory. The report explains gaps (image size, pretraining data, training budget).

## 8. CLI, layout and git

Layout:
```
configs/  src/{data,models,training,evaluation,visualization}/  src/cli.py
notebooks/  outputs/{NOTES.md,figures/}  README.md  requirements.txt  .gitignore  docs/
```

Commands (`python -m src.cli ...`): `eda`, `train --task classification --config <yaml>`, `tune --method grid|random --config <yaml>`, `predict --task classification --image <path>` (top-5, optional Grad-CAM overlay), `evaluate`, `gradcam`. `--task colorization` and `--task caption` are in the parser from the start and report "Milestone 2", so the CLI shape is final.

Git: scaffold on `main`, then short feature branches per member merged by PR. Small single-concern commits under each member's own identity. `.gitignore` covers datasets, `outputs/checkpoints/`, `wandb/`, `.env`, `__pycache__`. Claude drafts code and messages; the user runs `git push`.
